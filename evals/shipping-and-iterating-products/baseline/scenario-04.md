# Raw baseline output

Case ID: scenario-04
Reviewer ID: shipping-baseline-001

Do not perform a mandatory overnight replacement. The evidence shows a real benefit for new hires and a real regression for experienced dispatchers, so the rollout should preserve continuity while testing whether the redesign can serve both groups. A cleaner appearance is not a sufficient release criterion, and complaints alone should not veto a change if measured task performance and safety improve.

Instrument the existing and redesigned queues for task completion time, dispatch errors, shortcut use, recovery time after interruptions, abandoned actions, reversals, and support requests. Segment results by tenure, role, shift, case volume, and accessibility needs. Preserve the old keyboard shortcuts in the new layout where they do not conflict, add a shortcut reference and focused transition training, and test experienced dispatchers on realistic high-volume and interrupted workflows rather than only isolated mock tasks.

Release first as an opt-in or reversible pilot to a few units and shifts, with the old queue immediately available. Include new hires and experienced dispatchers in each pilot, and assign on-shift support. Compare within-user and between-group results across several real operating cycles. Review critical errors immediately and performance trends at predefined checkpoints; interviews and observation should explain measured problems, not replace the measurements.

Broaden the rollout only when the new-hire gains persist, experienced-user performance reaches an agreed non-inferiority threshold, interruption recovery is acceptable, and no patient-flow or dispatch safety metric worsens. If experienced users still regress, iterate on layout, shortcut compatibility, or transition design and rerun the pilot. Make the redesign the default only after those gates pass, retain a time-limited rollback path, and monitor for several weeks after expansion before retiring the old queue.
