## Runtime scope

Choose technical foundations, abstractions, ownership, and simplicity that increase a small team's product learning and output.

### Triggers

- Choose a technology, architecture, abstraction, or code ownership model for a startup.
- Reduce technical complexity that is slowing product iteration.

### Non-triggers

- Perform a routine implementation with no architectural choice.
- Choose which customer segment to pursue.

### Stage conditions

- Favor tools the team can use to ship now unless a specific product constraint creates durable leverage.
- Revisit ownership and decomposition as coordination costs begin to exceed local coding speed.

### Preserved tensions

- Unusual technical leverage versus hiring and ecosystem costs.
- Reusable abstraction versus premature generalization.
